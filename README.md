# RustyTracer

A small path tracer for learning Rust and rendering. JSON scenes describe a camera,
planes, and spheres with diffuse, metal, glass, or emissive materials. Rendering
uses the available CPU parallelism and saves RGB images as PNG or JPEG.

## Setup

The project uses Rust 2024 and pins Rust **1.99.1** in `rust-toolchain.toml` for
reproducible development. The minimum supported Rust version is **1.88.0**.
Install the development toolchain with [rustup](https://rustup.rs/):

```sh
rustup toolchain install 1.99.1 --profile minimal --component clippy --component rustfmt
```

Run commands from the repository root. Explicit `rustup run` commands also work
when a separately installed Cargo, such as Homebrew's, comes first on `PATH`.

## Render

```sh
rustup run 1.99.1 cargo run --release --locked
```

This loads `worlds/closed_room.json` and writes `output/image.png`, replacing the
previous image at that path. The default render is 200 by 100 pixels with 5,000
samples per pixel. Release mode is recommended for rendering performance.

The entry point in `src/main.rs` calls `tracer::generate`. To use a different scene,
output path, resolution, or sample count, call `tracer::generate_with_options` with
a `RenderOptions` value instead:

```rust
tracer::generate_with_options(
    "output/preview.png",
    "worlds/closed_room.json",
    tracer::RenderOptions {
        width: 320,
        height: 180,
        samples_per_pixel: 128,
    },
)
```

Output directories are created automatically. Supported output extensions are
`.png`, `.jpg`, and `.jpeg`. Dimensions and sample counts must be positive.
Rendering uses random sampling, so successive images will differ slightly.

## Scene format

The original scene format is preserved. See `worlds/closed_room.json` for a complete
example. Each position, normal, and RGB color must contain exactly three finite
numbers. Colors must be nonnegative, sphere radii must be positive, and plane
normals must be nonzero; the loader normalizes them automatically. Camera field
of view is measured vertically in degrees and must be between 0 and 180. The
camera must look in a nonzero direction that is not parallel to its Y up vector.

Material names are `flat`, `metal`, `glass` (refractive index 1.5), and
`diffuse_light`. Unknown material names retain the original flat-material fallback
and produce a diagnostic on standard error. Missing or malformed scenes produce
errors instead of panics.

## Development

```sh
rustup run 1.99.1 cargo fmt --all -- --check
rustup run 1.99.1 cargo clippy --locked --all-targets --all-features -- -D warnings
rustup run 1.99.1 cargo test --locked --all-targets --all-features
rustup run 1.99.1 cargo build --release --locked
```

Tests cover complete pixel coverage across different worker counts, exact sample
counts, tiny images, fractional and portrait aspect ratios, invalid scenes and
render settings, worker failures, glass total internal reflection, PNG/JPEG
round trips, and rendering the original closed-room scene. CI runs checks on Linux,
macOS, and Windows, including the minimum supported compiler on Linux.

The active renderer keeps camera, geometry, materials, scene traversal, JSON
loading, and pixel rendering in separate modules under `src/tracer`. The historical
`light.rs`, `photonmap.rs`, and `spectral.rs` experiments are outside the active
module tree.

Dependencies are [cgmath](https://github.com/rustgd/cgmath),
[rand](https://github.com/rust-random/rand), [image](https://github.com/image-rs/image),
and [Serde](https://serde.rs/) with serde_json. Image codecs are limited to PNG and
JPEG to keep the dependency tree small. `Cargo.lock` is committed; use `--locked`
for reproducible builds.
